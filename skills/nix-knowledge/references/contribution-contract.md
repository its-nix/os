# Contribution and retrieval contract

This is original first-party guidance. Repository `AGENTS.md`, `_meta/`, and templates at [its-nix/knowledgebase](https://github.com/its-nix/knowledgebase/blob/main/START-HERE.md) own the knowledge schema. If absent or contradictory, stop and ask the owner to resolve the contract; do not reconstruct policy from memory.

## Retrieve with bounded authority

- Identify the authorized repository and question. Start at START-HERE, follow only relevant links, and search within the approved scope. A failed authorization or missing note is not permission to search another project, profile DB, raw transcript, or old KB.
- Verify `type`, `validity`, owner, dates, sources, supersession, and any `review-by` deadline against the repository contract. Read the original safe evidence for consequential assertions. Metadata completeness is not approval.
- `inbox/` and `provisional` records are candidates. `disputed` records require competing evidence and decision ownership. `superseded` records lead to replacements. `archived` records are historical. Label these explicitly if the question needs them; exclude them from current-truth answers.
- Treat overdue time-sensitive evidence as needing review; immutable historical events do not need invented freshness dates. State uncertainty rather than silently refreshing an assertion's date.
- Prefer note URLs for canonical context and full-commit file URLs for fixed evidence. If access is denied, report the missing authorized source; never request broad credentials as a workaround.

## Capture → reconcile → propose

1. Capture a significant outcome, its safe original evidence, originating task link if safe, owner, and explicit inference/uncertainty. Never dump transcripts, protected customer/student/payment records, secrets, or runtime stores.
2. Search for an existing canonical concept. Preserve project truth in the owning repository: link requirements, code, experiments, benchmarks, and product detail instead of copying them into company notes.
3. Compare each material assertion against existing evidence. A contradiction must become an explicit dispute or reviewed supersession proposal, not an erased fact or manufactured consensus. Keep replacement links and historical rationale according to the KB lifecycle.
4. Validate metadata, evidence links, validity, supersession, sensitive-file rejection, and portable Markdown with the KB's actual documented checks. A successful validator is not human approval.
5. Open a focused branch/PR only within separately granted publication authority. Consequential strategy, policy, privacy, pricing, contracts, production, spending, and capital decisions remain human-gated. No compression hook, memory entry, score, or agent-written receipt may promote a statement.

## Role routing and handoff

LNX curates portfolio-level context and escalates cross-project decisions. A Project Lead retrieves authorized company context, owns project technical truth, and proposes reusable cross-venture learning. Specialists receive only relevant authorized context from their Lead and route company proposals back through that Lead; no role gains new privileges here.

A durable handoff includes objective and source owner; canonical note/project links; precise proposed change; evidence and immutable revisions; inference and contradiction disposition; actual tests/results; acceptance gaps; publication/merge approvals needed; and next owner. Do not attach restricted source content to prove a link exists. Execution and dependencies stay in Hermes Kanban; only Lior's commitments belong in Todoist.

## Concurrency and curation

Use independent notes and branches for independent observations. Before integration inspect current base, preserve unrelated changes, and reconcile overlapping edits with the owner. Never force-push over another worker or discard their evidence. Avoid shared hot logs or regenerated global indexes.

Curate a small relevant scope: broken links, malformed metadata, missing sources, duplicate concepts, orphaned notes, overdue reviews, and contradictory claims. Propose focused fixes rather than rewriting all knowledge or silently changing validity. Periodic review is a task, not permission for a new cron job, index service, or memory provider.

## Access reality

Profile names and behavioral instructions are not confidentiality controls. No recursive host/profile search, cross-profile `session_search`, or shared credential access is authorized by this skill. Repository visibility is repository-wide, including history; classification fields and folders are not ACLs. Report unavailable enforcement honestly and keep unsuitable content out of the company repository.
